Auto-Tagging Support Tickets Using LLMs
Project Overview

This project automatically classifies customer support tickets into predefined categories using Natural Language Processing and transformer-based language models.

The system analyzes the ticket subject and description, then returns the top three most probable tags with confidence scores. Three different approaches were implemented and compared:

Zero-shot classification
Few-shot classification
Fine-tuned DistilBERT
Objective

The objective of this project is to reduce the manual effort required to categorize customer support tickets. Automatically tagging tickets can help support teams route customer issues to the correct department and respond more efficiently.

Dataset

The project uses the Customer Support Ticket Dataset from Kaggle.

The following columns were used:

Ticket Subject
Ticket Description
Ticket Type

The ticket subject and description were combined into one text input, while Ticket Type was used as the target category.

The dataset contains five ticket categories:

Billing inquiry
Cancellation request
Product inquiry
Refund request
Technical issue
Approaches Used
Zero-Shot Classification

A pretrained zero-shot classification model was used to classify tickets without training it on the dataset. The model received the ticket text and a list of possible categories, then ranked the categories according to their probability.

Few-Shot Classification

Few-shot learning was implemented by providing the model with labeled examples from each ticket category. These examples helped guide the model before it classified a new ticket.

Fine-Tuned DistilBERT

The distilbert-base-uncased model was fine-tuned using the labeled support ticket dataset. The text was tokenized, converted into numerical labels, and divided into training, validation, and testing sets.

Evaluation Metrics

The models were evaluated using:

Top-1 Accuracy
Weighted F1-score
Top-3 Accuracy
Classification Report

Top-3 accuracy measures whether the correct ticket category appears within the first three predictions generated by the model.

Example Output

For a ticket such as:

I was charged twice for my subscription and want the extra payment returned.

The model may return:

Rank	Predicted Tag	Probability
1	Billing inquiry	0.72
2	Refund request	0.21
3	Cancellation request	0.04

The probability values depend on the trained model.
